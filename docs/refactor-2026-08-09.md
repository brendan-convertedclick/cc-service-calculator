# Conductor — full audit & refactor, 2026-08-09

Branch: `refactor/full-audit`. Production (`main`, served on :5391) was never touched.

## The headline

The codebase was not badly written. It was **ungated**.

`npm run typecheck` ran `tsc --noEmit` against a root `tsconfig.json` containing
`"files": []` and two project references. A references-only config type-checks
*nothing* and exits 0 in under a second. So the repo reported a clean typecheck
while `npm run build` had been failing for an unknown length of time with 63
errors. ESLint was never installed at all — `npm run lint` was `sh: eslint:
command not found`. There was no `.github/`, no CI, and no pre-commit hook.

Nothing in this repository was capable of failing. Every symptom below follows
from that.

## The pathology, measured

The suspicion — that agents duplicate rather than reuse — held up, and it was
measurable. In every case a correct shared helper *already existed* or was
trivially derivable; the duplicate was written next to it anyway.

| Idiom | Before | After | Why the duplicate was worse |
| --- | --- | --- | --- |
| `e instanceof Error ? e.message : "…"` | 105 | 1 | `errorMessage()` existed. A Supabase `PostgrestError` is a **plain object**, so the check is always false — **every database error in the app showed a generic fallback instead of the real message** |
| Hand-rolled edge-function fetch | 28 across 18 private `FUNCTIONS_BASE` consts | 3 (deliberate) | now `callEdgeFn()`; the 3 remaining use different auth or tolerate non-2xx |
| 5-line `new Set(prev)` toggle | 23 | 9 (not real toggles) | now `toggleInSet()` |
| `new Date().toISOString().slice(0,10)` | 11 | 2 | returns the **UTC** date — wrong for SAST between 00:00–02:00 |
| Inline ZAR `Intl.NumberFormat` | 15 | 7 (differing options) | `formatZar()` existed |
| Inlined filter rail | 4 pages + 4 private row components | 1 shared module | `Escalations.tsx` already had a clean extraction nobody reused |

Two findings capture the pattern exactly:

- **`RequireRole.tsx` was dead** because `App.tsx` had reimplemented it inline as
  a local `RequireAdmin`. The gating works; the shared component rotted.
- **`SystemCanvas.tsx` carried an `eslint-disable` comment** for a linter that
  had never been installed.

## Bugs found and fixed

The broken build was hiding real defects. Three share one shape — a field read
off an object that never had it, silently yielding `undefined`:

1. **`am_notes` (5 sites).** Read off a `brief` row; the column lives on
   `brief_intelligence`. The account manager's notes never reached the Claude
   prompts in Inbox/ProjectBuilder, and never rendered in ProjectScopeView.
   `Scope.tsx` did it correctly, which is how the intent was recoverable.
2. **Xero tenant name.** `useXeroConnectionStatus` selected only `updated_at`,
   so Settings' connected-organisation name was always blank.
3. **Productivity charts.** `DeliveryRateChart`/`DeliveryValueChart` didn't
   filter team members lacking a `clickup_user_id`, emitting duplicate React
   keys and permanently-empty bars for unlinked staff.
4. **Invoice-run CSV dates.** `Reports.tsx` stamped cycle boundaries with the
   UTC date, so the CSV's date label and filename could show the wrong day.
5. **A live deploy landmine.** 64 edge functions exist; `supabase/config.toml`
   declared `verify_jwt = false` for only 31. The API gateway cannot validate
   this project's ES256 user tokens, so the next plain
   `supabase functions deploy <fn>` on any of the other 33 would have returned
   401 to every caller. All 64 are now declared.
6. **14 stale `@ts-expect-error` directives** suppressing errors that no longer
   existed — evidence of suppression as a habit rather than a decision.

## Found, deliberately not fixed

Reported rather than changed, because each needs an owner's judgement or a
production redeploy mid-refactor:

- `SettingsConnectGoogle.loadStatus` doesn't check `res.ok`; a server error is
  cast to `GoogleStatus` and renders as "not connected".
- `Settings.tsx`'s `xero-oauth?action=disconnect` authenticates with the anon
  key rather than the user's session token.
- `ReconciliationView` and `LiveTasksInvoicePreview` render ZAR with 2 decimals
  while the rest of the app renders 0. A display decision, not a mechanical fix.
- `push-to-clickup` reimplements `resolveDropdownOption` inline and has drifted
  to a case-sensitive field match, unlike the tested `_shared` version.
- The tested `cuFetch` 429-retry wrapper has **zero adopters**; 39 raw ClickUp
  fetches across 35 functions are unprotected against rate limiting.
- Three edge functions have no caller anywhere (`match-tasks-to-sow`,
  `setup-unallocated-ai-bucket`, `draft-scope`). Deleting repo files does not
  undeploy them — that needs a deliberate server-side removal.
- Xero OAuth token refresh is reimplemented in 4 functions; the three `notify-*`
  functions share a ~90-line body.

**Edge-function policy for this pass:** repo edits don't reach production until
`supabase functions deploy` runs per function. Rewriting them would have left
the repo and production silently divergent, so this pass took only `config.toml`
(which fixes a latent outage without changing behaviour) and left the
consolidations documented above.

## The systems that stop it recurring

The fixes matter less than the gates.

- **`npm run typecheck` is now `tsc -b`.** The single change that would have
  prevented most of this.
- **ESLint on a ratchet.** Clean rules are `error`; the pre-existing backlog is
  `warn` with a CI cap that only moves down (57 → 47 during this work). Two
  rules encode project conventions mechanically: no inline `Intl.NumberFormat`
  outside `lib/format.ts`, no second `createClient`.
- **`react-hooks/exhaustive-deps`** — the highest-value rule for agent-written
  React, previously unenforceable.
- **knip in CI** — fails on files nothing imports. Dead files went 11 → 0.
- **CI** — typecheck, lint, dead-code, unit tests, build, and Playwright.
- **`CLAUDE.md` now carries a "Reuse before you write" table** mapping each need
  to its helper and the anti-pattern it replaces. This is the artifact future
  agents actually read, and it is why the same duplication should not reappear.
- **Characterization e2e** (`e2e/filter-rail.spec.ts`) pins rail behaviour so
  the consolidation is provably behaviour-preserving.
- Optional local hook: `git config core.hooksPath .githooks`.

## Deliberate non-goals

- `ServicesList` and `SowList` keep their own rails — their markup differs
  enough that sharing would have cost more props than it saved. A component
  with eight boolean props is worse than the duplication it replaces.
- No top-level `<FilterRail>` wrapper, for the same reason; the shared piece
  stops at `FilterGroup`/`FilterOption`.
- `src/types/db.ts`, `src/styles/tokens.*` (generated) and
  `supabase/migrations/` (immutable history) were not touched.
- `e2e/systems.spec.ts` **writes to the live database**. It was excluded from
  the automated gate and should be run deliberately.
